# 退去立会い・原状回復チェック

## 概要

賃貸の管理会社・小さな不動産会社の担当者が、スマホで退去立会いの確認結果を残し、精算見積の下書きまで作る業務アプリです。デモ用の架空データです。

## 主な機能

### 部屋ごとのチェックと写真

物件・号室・間取り・入退去日・借主・立会い者・敷金を登録すると、間取りに応じた部屋とチェック項目を展開します。各項目に状態、原因、具体的なメモ、複数の写真を記録できます。写真は長辺1600px以内に縮小し、部屋と項目のラベルを重ねて表示します。

### 負担区分

原因から貸主・借主・保留を提案します。クロス・CF等の参考負担割合を自動計算し、担当者が区分・割合・償却の適用を変更できます。チェック設定ではテンプレート・単価・クリーニング特約の既定を編集できます。既存の立会いの設定は保持します。

### 精算見積の下書き

単価×数量×負担割合から貸主・借主それぞれの明細、小計、消費税10%、敷金との差額を計算します。保留項目は請求額から除外し、未確認項目も明示します。クリーニングは特約確認時のみ借主負担です。BOM付きCSV、A4縦の印刷・PDF保存に対応します。印刷は表紙、明細、1ページ最大12枚の写真一覧に分かれます。

## 日時と入居年数の扱い

初回起動・既定データへの復元時に、開いた時点の日本時間から相対的にシードを生成します。表示は日付 `YYYY-MM-DD`、時刻 `HH:MM`。実施済みの立会い・写真は過去、今後の予定のみ未来です。0時台でも当日完了の記録は生成しません。

入居月数は入居日と退去日の満月数です。月末の応当日は対象月の最終日に丸めます（1月31日→2月28日、うるう年は2月29日）。一覧の経過日数は開いた時点の日本日付と退去日の暦日差です。新規写真の日時は記録時刻です。未来の立会いは実施済みにできません。

## 負担割合の計算について

国土交通省「原状回復をめぐるトラブルとガイドライン」の考え方を参考にした簡易計算で、法的判断ではありません。通常損耗・経年劣化は貸主、故意・過失・善管注意義務違反は借主を初期値として提案します。

クロス・クッションフロア等の工事費を `C`、入居月数を `M` とした参考式：

```text
借主負担割合 = [1円 + (C − 1円) × max(0, 1 − M ÷ 72)] ÷ C
```

0か月で100%、36か月で残存1円を含めて約50%、72か月以降で1円相当になります。工事費0円では割合0、工事費が1円未満の場合はその工事費を上限とします。入居前の施工時期や残存使用年数は自動取得しません。フローリング全面張替えなど6年償却に適さない項目は適用を解除してください。

工事費の1円未満を切り捨てた後、借主負担を切り捨て、残額を貸主負担にします。税額は負担者ごとの小計×10%を切り捨てます。上書きした割合を優先します。特約の有効性、故意・過失、補修の範囲、経過年数は担当者が確認してください。

## 既存作品との違い

| 既存作品           | 主な対象                 | このアプリの対象                     |
| ------------------ | ------------------------ | ------------------------------------ |
| 契約管理システム   | 契約書・契約期間・更新   | 退去時の部屋の状態・原因・写真       |

## データの保存先

- メタデータ：localStorage、キー `moc:v1`
- 写真：IndexedDB、DB名 `moc-photos`、ストア `photos`
- PWA用のアプリ資材：Cache Storage、`moc-shell-v1`
- JSONバックアップ：利用者がダウンロードしたファイル。写真をbase64で含む

保存データの形式・参照関係を検証します。破損している場合は通知して既定データへ戻します。不正なバックアップは読み込まず、現在のデータを維持します。読み込み時は件数と写真枚数を確認してから置換します。ブラウザの保存容量不足は通知します。端末間の自動同期はなく、複数タブでの同時編集は避けてください。端末変更・ブラウザデータの削除前にバックアップしてください。

## ローカル起動方法

このプロジェクトの `move-out-inspection-check` フォルダ直下で実行します。テストにはTypeScriptを直接実行できるNode.js 24以降を利用してください。

```sh
npm run dev
```

本番ビルド・起動：

```sh
npm run build
npm start
```

品質チェックと整形：

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

Service Workerは本番起動時のみ登録します。最初のオンライン表示後に読み込んだアプリ資材をキャッシュし、オフラインの画面遷移では共通シェルを返します。アプリ更新時にはキャッシュのバージョンを更新してください。

静的書き出し（PowerShell）：

```powershell
$env:MOC_STATIC_EXPORT = "1"
npm run build
Remove-Item Env:MOC_STATIC_EXPORT
npm run preview:static
```

`out/` が生成されます。静的ホストでは `/inspections/*` を `/index.html` にHTTP 200でフォールバックする設定が必要です。対応ホスト向けの `_redirects` を同梱しています。他のホストは同等のSPAフォールバックを設定してください。通常のNext.js起動では `next.config.ts` のrewriteで共通シェルを返します。IDはマウント後にURLとlocalStorageから読み取り、シードにない新規IDでも開けます。内部遷移はHistory APIを使います。`turbopack.root` はプロジェクト直下を維持します。

ブラウザ検証用の `scripts/verify-browser.mjs` は、既存のPlaywright Coreのパスを環境変数 `PLAYWRIGHT_CORE_PATH` に設定して、起動中の本番サーバーに対して実行できます。依存パッケージの追加は不要です。撮影は行いません。検証プロファイルは `.cache/browser-check` に作られ、終了時に削除します。

## デモデータについて

みずほし不動産管理（架空）の立会い5件を収録しています。実施済み3件（見積下書き済み2件、未作成1件）と予定2件です。入居期間は1年半・4年・7年などで異なります。ペット可住戸の爪の跡、ヤニ、通常損耗による日焼け、ほぼきれいな住戸を個別に設定しています。

24枚のイラストはcanvasで描画し、隅に「サンプル画像」を表示します。物件名・借主名・記録時刻・メモを循環する配列で機械的に割り当てず、物件ごとの状況を設定しています。「このデモについて」から現在の日本時間を基準に既定データを生成し直せます。
